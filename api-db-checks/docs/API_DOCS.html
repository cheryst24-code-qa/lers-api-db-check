LERS SERVER API — Документация

На этой странице представлена HTML‑версия документа API_DOCS.md, подготовленная для размещения на сайте или внутреннем портале.

Обзор

LERS SERVER API предоставляет HTTP‑интерфейс для работы с системой учета ресурсов:

  • Авторизация и управление сессией
  • Работа с объектами учета (дома, узлы и пр.)
  • Работа с точками учета (приборы учета)
  • Работа с оборудованием
  • Управление инцидентами (НС)
  • Получение служебной информации о сервере
  • Работа с территориями и погодными данными
  • Календарь событий

Базовый URL:

{{baseUrl}}/api/v1/...

Рекомендуется использовать отдельные окружения для dev / stage / prod (см. раздел «Окружения»).

Аутентификация

Общие принципы

Большинство эндпоинтов требуют аутентификации по токену доступа.

  1. Выполнить логин: POST /api/v1/Login
  2. В ответе получить токен доступа и (опционально) время его истечения.
  3. Сохранять токен и передавать в заголовке: 
    Authorization: Bearer <token>
  4. Для проверки корректности авторизации: GET /api/v1/Login/Current

POST /api/v1/Login

Аутентификация пользователя по логину и паролю.

Тело запроса (пример)

{
  "login": "demo",
  "password": "secret"
}

Ответ 200 (пример)

{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresAt": "2025-01-01T00:00:00Z",
  "user": {
    "id": 123,
    "login": "demo",
    "fullName": "Иван Иванов",
    "roles": ["Admin"]
  }
}

Ошибки

  • 401 Unauthorized — неверный логин или пароль.
  • 400 Bad Request — некорректный формат тела запроса.

GET /api/v1/Login/Current

Информация о текущем аутентифицированном пользователе.

Заголовки

Authorization: Bearer <token>

Ответ 200 (пример)

{
  "id": 123,
  "login": "demo",
  "fullName": "Иван Иванов",
  "roles": ["Admin"],
  "email": "user@example.com"
}

Ошибки

  • 401 Unauthorized — токен отсутствует или недействителен.

Окружения и переменные

Рекомендуется использовать три основных окружения:

  • Dev — среда разработки
  • Stage — стейджинг (тестовый стенд)
  • Prod — боевая среда
Dev:   baseUrl = https://dev-lers.example.com
Stage: baseUrl = https://stage-lers.example.com
Prod:  baseUrl = https://api-lers.example.com

Общие переменные во всех окружениях:

  • baseUrl — базовый URL сервера.
  • login — логин пользователя.
  • password — пароль пользователя.
  • auth_token — токен авторизации (из /api/v1/Login).
  • token_expiration — время истечения токена.

Часто используемые переменные:

  • start — начало периода (например, 2024-01-01T00:00:00Z).
  • end — конец периода (например, 2024-01-31T23:59:59Z).

Структура API

Высокоуровневые разделы:

  • Авторизация: /api/v1/Login, /api/v1/Login/Current
  • Объекты учета: /api/v1/Core/Nodes, /api/v1/Core/NodeGroups, /api/v1/Core/NodeJobs
  • Точки учета: /api/v1/Core/MeasurePoints, /api/v1/Data/MeasurePoints/...
  • Оборудование: /api/v1/Core/Equipment/...
  • Инциденты (НС): /api/v1/Incidents/...
  • Информация о сервере: /api/v1/ServerInfo...
  • Территории и погода: /api/v1/Core/Territories, /api/v1/Data/Territories/...
  • Календарь событий: /api/v1/Analysis/EventCalendar/...
  • Удалённое управление: /api/v1/Plugins/Web/...

Объекты учета

GET /api/v1/Core/Nodes

Список объектов учета (зданий/узлов), доступных пользователю.

Пример ответа

[
  {
    "id": 95,
    "name": "Дом 10, корпус 2",
    "address": "г. Город, ул. Примерная, д.10, к.2",
    "groupId": 1,
    "groupName": "Центр",
    "isActive": true
  }
]

PATCH /api/v1/Core/Nodes/{id}

Частичное обновление свойств объекта учета.

Параметры: id — идентификатор объекта учета.

Тело запроса (пример)

{
  "name": "Дом 10, корп. 2 (обновлено)"
}

Пример ответа

{
  "id": 95,
  "name": "Дом 10, корп. 2 (обновлено)",
  "address": "г. Город, ул. Примерная, д.10, к.2",
  "groupId": 1,
  "isActive": true
}

GET /api/v1/Core/Nodes/{id}/MeasurePoints

Список точек учета, связанных с указанным объектом учета.

Параметры: id — идентификатор объекта учета (пример: 95).

GET /api/v1/Core/NodeGroups

Список групп объектов учета, доступных пользователю.

Пример ответа

[
  {
    "id": 1,
    "name": "Центр",
    "description": "Центральный район"
  }
]

GET /api/v1/Core/NodeJobs

Список работ/заданий по объектам учета.

Пример ответа

[
  {
    "id": 1001,
    "nodeId": 95,
    "type": "Maintenance",
    "status": "Planned",
    "scheduledAt": "2024-02-01T08:00:00Z"
  }

Статусы ответов и ошибки

Типичные коды:

  • 200 OK — успешный запрос.
  • 201 Created — ресурс создан (например, при создании инцидента).
  • 204 No Content — успешный запрос без тела ответа.
  • 400 Bad Request — некорректные входные данные.
  • 401 Unauthorized — неавторизован (нет токена/токен недействителен).
  • 403 Forbidden — недостаточно прав.
  • 404 Not Found — ресурс не найден.
  • 500 Internal Server Error — внутренняя ошибка сервера.

Рекомендации по мониторингу

Рекомендуется регулярно проверять:

  • /api/v1/Login — работоспособность авторизации.
  • /api/v1/Login/Current — корректность токенов.
  • /api/v1/Core/Nodes и /api/v1/Core/MeasurePoints — основные справочники.
  • /api/v1/ServerInfo — доступность сервера и версию.

Критерии:

  • Код ответа не 5xx.
  • Время ответа < 1500 мс (или ваш SLA).
